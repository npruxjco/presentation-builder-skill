# 通用敘事規則

適用所有報告類型。專案自己的命名、符號與禁區規則優先於本檔。

## 標題

- 使用正式、清楚、具體的敘述式標題，讓第一次看到該頁的人就知道這頁的主題。
- 不使用問句標題，也避免口語、模糊的說法。
- 方法或流程頁用名稱；結果頁用主題，或有已驗證證據支持的發現。不要求每個標題都是結論。

| 不建議 | 建議 |
|---|---|
| 這個結果穩嗎？ | 排除特殊資料後的敏感度分析 |
| 我們這週做了什麼？ | 本週完成事項與驗證狀態 |

## 誠實性

1. 標題不誇大證據，不為了吸引人加入未驗證的因果敘述。
2. 頁面上要看得出三種內容：**已完成並驗證**、**完成但尚未驗證或串接**、**尚未做**。尚未產出的結果只寫狀態，不放預期數字。
3. 數字只用來源文件已有的，不自行重算或推測；每個數字附分母與來源。數字與來源不符時以來源為準並回報。
4. 不替作者編造問題、結論或待確認事項。「想請對方確認的事」只列作者提供的項目。
5. 舊做法的問題與新做法要分開講，避免讓聽眾以為現在仍有同樣問題。

## 分隔頁與章節進度列

- 每個主要章節以分隔頁開頭；分隔頁只放章名，並用一行說明「這章要回答什麼」。
- 內容頁頂端放章節進度列：列出全部章節，目前章節強調，其餘灰色。
- 分隔頁不占報告時間。

## 主題與主題的串接

- 章與章之間用一句話交代「上一章留下什麼、這一章要回答什麼」，放在分隔頁的說明行或下一章首頁。
- 每頁都能回答：為什麼放這頁、這頁說明什麼、為什麼接著是下一頁。答不出來，先檢查這頁是否必要。
- 順序優先順著聽眾的疑問走：結論 → 依據 → 限制 → 下一步；需要對方決定的事放在最後並事先預告。

## 流程型章節的連貫性

章節若用多頁說明同一流程的連續步驟，不得每頁各講各的：

1. 章首放流程總覽頁：列出每個步驟與「本步產出」，註明上一步的產出就是下一步的輸入；若是迴圈，寫出怎麼接回第一步。
2. 每個步驟頁頂端放進度列：列出全部步驟，目前這步強調，其餘淡化；強調與淡化的具體做法（例如已完成步驟是否也上色）由風格決定。
3. 進度列下放一行銜接列，格式「承接（上一步給了什麼）→ 本步產出 → 交給（下一步拿它做什麼）」；只占一行，放不下就縮短文字。
4. 不屬於單一步驟的頁面也放進度列，同時標出涉及的所有步驟。
5. 加了進度列與銜接列後內容整體下移；不得因此縮小字級或刪掉重要說明。

## 講者備註

- 備註要完整到簡報者不看投影片也能講清楚圖表讀法、發現與意義。
- 第一句交代銜接，例如「第三步，把第二步的結果和第一步的排名放在一起」，再進入本頁內容。
- 結果頁備註要有「不能成立的推論」。

## 圖表

- 每張圖標 n 與分母；直接引用既有圖檔，不重畫、不修改；需要新示意圖（流程圖、數線）才另畫。
- 一圖一頁，除非是同口徑並排比較且仍然可讀。
- 不使用 emoji。

## 命名與符號

- 只用專案文件規定的名稱與符號；第一次出現寫成「中文名稱（符號）」並說明。
- 圖上不放符號，用白話。
- 不自創名稱。專案沒有規定時，先問使用者再定。
