# 專案進度報告模組

用在週報、月報、專案進度與需要對方決策的報告。與 `narrative-core.md` 一起使用。

## 建議敘事順序

1. 摘要：用一句話說本期最重要的結論，必要時附一張流程圖。
2. 完成事項：依主題分章，說明做了什麼、結果、與目標的關係。
3. 目前驗證狀態：哪些已驗證、哪些完成但未串接、哪些尚未做。
4. 後續工作與依賴：下一步，並標出需要等別人的部分。
5. 待確認事項：需要對方決定的事，放最後，並在前面預告。
6. 附錄：欄位表、設定表等查閱用內容。

## 檢查項目

1. **目標與範圍**：本報告涵蓋誰的哪一部分；他人負責的部分只在串接處提到並說明原因。
2. **里程碑與狀態**：列出主要里程碑與目前狀態；完成、進行中、延遲分開，不把「程式完成」說成「已驗收」。
3. **驗證狀態表**：每個數字附項目與條件，例如測試數、通過數；沒做的項目明列「尚未做」與原因，不留白。
4. **風險與依賴**：寫出等誰、等什麼，避免對方誤以為已完成。
5. **待確認事項**：每項要有背景、現況、選項與取捨、需要誰決定，以及作者的傾向（若有）；先給聽眾決定所需的資訊，再給問題。
6. **範圍外的事**：明確寫出不做或延後的項目與理由。
7. **來源檢查**：待確認事項的編號或分類若不連續或缺漏，先問作者，不自行補。

## 待確認事項的分組

事項多時依主題合併成幾頁（例如資料與權限、指標定義、跨團隊依賴、驗收方式），並在章首頁放總覽，先讓對方知道有幾項、各屬哪組。
